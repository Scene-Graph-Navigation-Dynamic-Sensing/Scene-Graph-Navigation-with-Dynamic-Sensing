stage 5b

Crop and embed

Each detection is cut out of the frame and turned into a list of 1024 numbers by a CLIP image encoder. Two crops of the same thing give nearly the same numbers, so "do these look alike?" becomes a single number: the cosine similarity. This embedding is used for matching in fusion and, averaged per object, for naming.

NOVIC's embedder: OpenCLIP apple/DFN5B-CLIP-ViT-H-14-378 · 378 × 378 input · 1024-d output · runs on the embedding thread, batched, on one or more GPUs

Try it: the crop CLIP actually sees

Drag on the frame to draw a detection box. The pipeline pads the box by 15% of its own size on each side (crop_padding_frac: 0.15), so a small object keeps some context and a large one is not swamped by background.

Why not the segmented crop? Tested on real crops: blacking out the background makes CLIP confident and wrong (desk clutter decoded as "conch" 0.82). The plain padded box keeps the context CLIP was trained on.
