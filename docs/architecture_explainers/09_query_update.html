Using the graph: task planning and scene update

The saved scene graph is the robot's memory. A command is grounded to one of its nodes and turned into a path; a new video of the same room changes only the nodes that changed.

Task planning: from a command to a goal

1 · Command

"bring me the mug next to the laptop"

2 · Gemini 2.5 Flash

gets the graph as text (node ids, names, parents, relations) and picks the target node

3 · NOVIC similarity tool

if names are ambiguous, Gemini calls a local tool: the query's text embedding vs each candidate's stored image embedding. Embeddings never leave the machine.

4 · Goal + path

the node's saved centroid → A* on an occupancy grid from the voxel map

Try it: the occupancy grid and A*

Cells are 5 cm. A cell is occupied when ≥ 100 map points lie in it between 0.2 m and 1.4 m above the floor (the robot's height band); occupied cells are inflated by the robot radius (0.4 m) before A*. Click cells to add or remove obstacles; shift-click to move the goal.

Scene update: change only what changed

A new video of the same room goes through the same detection and track fusion, but fusion starts from the saved objects instead of an empty map.

  1. Relocalise the new video in the saved map: SuperPoint + LightGlue matches between keyframes of both runs, lifted to 3D, a RANSAC similarity transform (two monocular runs need not share a scale), then ICP.
  2. Find removed space: a saved voxel is deleted when the new video sees through it (observed depth beyond it, most views agreeing).
  3. Remove objects with more than half of their voxels deleted.
  4. Fuse the new tracks against saved objects at the stricter 0.75 score (DoVSG's value); a matched saved object keeps its node and name.
  5. Add new objects only if ≥ 40% of them is space the saved map had empty, and NOVIC names them confidently.
  6. Update the graph: removed nodes go (their dependants are placed again); new objects are placed with the same on / inside / belongs rules; every other node stays.
