Track accumulation and commit

Fusion turns many 2D detections into one 3D object per real thing. It works per track, not per detection: everything BoT-SORT calls the same id is piled up first, and only when the track ends is the whole pile compared with the map — once, with many views of evidence.

The life of a track

  1. Detection arrives with its mask voxels (from the voxel map's pixel lookup, mask eroded by 2 px), its embedding and its track id.
  2. No id (−1)? It is a one-detection track and is committed immediately.
  3. Known id: voxels are joined into the pending track; the embedding joins a running average. If the new detection's cosine to the track so far is below 0.6, the tracker probably handed the id to another object: the old pile is committed and a new one starts (track_split_cosine).
  4. Unseen for 10 frames → commit: DBSCAN removes stray voxels, then the track is scored against every map object.
  5. Best passing object → merge (voxel union, detection-weighted average embedding). None passes → a new map object.
  6. NOVIC decodes the object's averaged embedding into a name (track_names), so naming is ready when the video ends.

Every 20 frames all objects built so far are cleaned with DBSCAN (denoise_interval).

Try it: the commit decision

Set the three numbers fusion computes between a committing track and its closest map object, or load a real commit from the office_0 log.

Why the containment gate: a bottle standing on a table touches the table only where it stands (0.19 of its voxels, laptop 0.06), while a second view of the same object lies 0.4–1.0 inside it. Why the cosine gate: an object flush against a wall overlaps it fully (geometric ≈ 1.0) and would merge at cosine ≈ 0.55 without it; on office_0, 8 of 16 such merges had cosine < 0.75.
